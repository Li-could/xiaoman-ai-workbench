# 淘宝 / 天猫 开放平台接入指引

> 本文对应代码：`lib/connectors/taobao.js`、`lib/store-auth.js`、`lib/sync.js`
> 目标：把「添加店铺」从演示数据改成**真实调用淘宝接口**。没有 AppKey 时系统会明确报错，不会伪造成功。

---

## 一、先搞清楚：哪些能力能真接，哪些接不了

| 能力 | 接口 | 前置条件 |
|---|---|---|
| 店铺信息 | `taobao.shop.seller.get` | 应用上线 + 卖家授权，基础权限 |
| 卖家账号 | `taobao.user.seller.get` | 同上 |
| 已卖出订单 | `taobao.trades.sold.get` | 交易类目权限，只能查近 3 个月 |
| 收到退款 | `taobao.refunds.receive.get` | 退款类目权限 |
| 在售商品 | `taobao.items.onsale.get` | 商品类目权限 |
| 平台消息（订单/退款事件） | `taobao.tmc.messages.consume` | 消息服务权限 + 订阅 topic |
| **买家聊天内容** | 千牛客服 / 客服机器人 | **需企业入驻服务市场并签约客服能力，个人应用拿不到** |

最后一行是硬限制。系统里「接口能力」表会把它标为不可用，不会假装能收发聊天消息。

## 二、申请流程（一次性）

1. **注册开放平台账号**
   <https://open.taobao.com> → 用淘宝/天猫账号登录 → 完成实名认证。
   企业入驻需要营业执照；个人开发者只能申请极少类目。

2. **创建应用**
   控制台 → 应用管理 → 创建应用 → 选择「自用型应用」（自己店铺用，不需要 ISV 签约）。
   创建后拿到 **AppKey** 与 **AppSecret**，这就是要填进本系统的两个值。

3. **配置授权回调地址**
   应用详情 → 安全设置 → 授权回调地址，填：

   ```
   http://127.0.0.1:8787/api/oauth/taobao/callback
   ```

   > 用 `localhost` 还是 `127.0.0.1`、端口是多少，取决于你在浏览器里怎么访问本系统。
   > 系统「添加店铺 → 用 API 接入」页面上会显示当前应当填写的完整地址，直接复制即可。
   > 若平台不允许 localhost，用 cloudflared 之类的内网穿透拿一个 https 临时域名，
   > 然后把它写进 `.env` 的 `PUBLIC_BASE_URL`。

4. **申请接口权限**
   应用详情 → 接口权限 → 按需申请：交易、退款、商品、消息服务。
   审核通常 1–3 个工作日。权限没批之前调用会返回 `11`（权限不足）。

5. **应用上线**
   开发调试阶段用「沙箱环境」；要读真实数据必须让应用处于**上线**状态。

---

## 三、在本系统里完成接入

1. 进入「店铺管理」→ 添加店铺 → 左侧选 **淘宝 / 天猫 / 淘工厂**。
2. 点右上「用 API 接入」。
3. 填 AppKey、AppSecret，环境选「正式环境」。
4. 点 **仅验证凭据**：
   系统会真实请求 `taobao.time.get`（不需要授权的公共接口），
   - 通过 → 说明 AppKey / AppSecret / 签名三者一致；
   - 不通过 → 直接显示淘宝返回的原始错误码，例如
     `[29] Invalid app Key / isv.appkey-not-exists`。
5. 点 **保存并去授权** → 打开淘宝授权页 → 用该店铺的卖家账号登录并同意。
6. 授权完成浏览器跳回本系统，自动调用 `shop.seller.get` + `user.seller.get`，
   把**真实店铺名、店标、掌柜号**写回店铺卡片。

## 四、消息怎么进来（本机也能收）

淘宝消息服务（TMC）支持两种消费方式：

- 长连接（官方 Java/C# SDK 才支持）
- **API 拉取**：`taobao.tmc.messages.consume` + `taobao.tmc.messages.confirm`

本项目用第二种，**不需要公网域名**，本机跑就能收。
`lib/poller.js` 默认每 60 秒拉一次（`.env` 的 `TMC_POLL_MS`，设 0 关闭）。

拉到消息后：
- 原样落到 `tmc_messages` 表（按消息 ID 去重）；
- 写入「信息通知」；
- 退款类事件自动生成工单 + 会话，进入「售后助手」。

要让某个店铺真正收到消息，还需要在开放平台后台**订阅对应 topic**（如交易、退款类）。

## 五、数据结构

| 表 | 用途 |
|---|---|
| `store_credentials` | 凭据。AppSecret / access_token / refresh_token 全部 AES-256-GCM 加密 |
| `connector_logs` | 每次真实接口调用记录（接口名、成功与否、错误码、耗时） |
| `shop_orders` / `shop_refunds` / `shop_items` | 同步下来的真实订单 / 退款 / 商品 |
| `tmc_messages` | TMC 原始消息，按 msg_id 去重 |
| `store_knowledge` | 店铺知识（商品ID / 问题 / 答案），右键「导入知识」写入 |

加密密钥在 `data/secret.key`（首次启动自动生成，权限 600）。
**这个文件不要删、不要提交到 git**，删了之后已存的 AppSecret 和 token 都解不开，只能重新授权。

## 六、常见错误码

| code | 含义 | 处理 |
|---|---|---|
| `29` / `isv.appkey-not-exists` | AppKey 不存在 | 核对 AppKey，或环境选错（沙箱/正式） |
| `25` / `isv.invalid-signature` | 签名错误 | AppSecret 不对，注意别把前后空格复制进来 |
| `21` / `22` | 缺少 / 失效 session | 店铺没授权或授权过期，点「重新授权」 |
| `11` | 权限不足 | 到开放平台申请对应接口权限 |
| `7` | 应用调用受限 | 应用未上线，或当日流量包用尽 |
| `26` | 时间戳无效 | 本机系统时间不准 |

所有错误都会同时写入 `connector_logs`，在「接入详情 → 最近接口调用」里可以看到。

---

## 七、上线前必须做的事

1. 把 `data/secret.key` 纳入备份，或改用 `APP_SECRET` 环境变量统一管理。
2. 关掉 `.env` 里的沙箱环境，确认 `env=prod`。
3. 若部署到公网，把 `PUBLIC_BASE_URL` 设成正式域名，并在开放平台同步更新回调地址。
4. TMC 轮询会消耗接口流量包，多店铺时适当调大 `TMC_POLL_MS`。
